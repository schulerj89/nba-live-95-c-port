# Indexed intro resources and native font rendering

This is a bounded artwork/rendering repair. **The complete cold-boot intro is
still incomplete:** license/legal waits, permitted skip input, EA holds, audio
commands, and resource handoff scheduling do not yet reproduce the ROM. No
whole-game or whole-intro completion claim follows from these results.

## Production resource boundary

Reproduce the required native capture with tracked tools (the output directory
must not already exist):

```powershell
python tools/capture_intro_indexed.py --rom 'F:\Games\SNES\NBA Live 95 (USA).sfc' --output .analysis/intro-exact-20260830/capture-v4
```

The runner creates a private Mesen executable/settings/save home, uses an
explicit per-child environment, and requires the pinned ROM, Mesen and Lua
identities. It does not change the user's emulator. The exact Lua bytes are
tracked with LF line endings. Existing accepted captures need not be rerun or
overwritten. A new location can be supplied to extraction via
`NBA95_INTRO_RESOURCE_DIR`; the documented default is the directory above.

`tools/extract_assets.py` now builds resource75 (`NBEAIDX1`) and resource76
(`NBITEXT1`) through `build_intro_indexed.py`. The runtime loads both from the
asset pack. It neither opens capture files nor runs an emulator to draw them.
Startup fails clearly if the pack lacks these resources; the embedded Nintendo
license fallback is no longer used.

The extractor removes old graphics IDs1–6 and70–74. In particular, it no longer
reads `legal.png`, EA stage screenshots, or eleven captured flash images, and
no longer embeds handwritten `license_rows`. Existing individual BRR-derived
audio resources and assembled intro audio7 are unchanged. **Audio7 still uses
the wrong host sequence/timing and is not accepted as native audio parity.**
It is assembled from decoded ROM voice samples, not a recorded song.

| 75, 71,674 bytes | Initial indexed Mode7 VRAM; final OBJ character bytes; initial CGRAM; four palette groups; E/EA OAM; A/SPORTS tilegroups | VRAM/OAM/CGRAM come from attested, untouched ROM execution. ## Translated behavior and references

| C implementation | Native owners / bounded recomp counterparts | State and behavior |
|---|---|---|
| `nba_ea_intro.c` | `82:F15C-F4C3`, `F4C4-F67D`; `IntroBuilder`, `EASequence`, `IntroFlash`, `Draw{E,A,Sports}Layer`, `Mode7Zoom`, `StepPalette`, `StepPaletteGroup` | Logical motion frame replaces the frame-wait continuation for the tested animation interval. Matrix `$0836/$0838`; palette work `$0828/$082E/$0830`. Integer Mode7 products retain separate six-bit truncation. Palette stepping includes index0 and abandons the remaining inner steps when all sixteen colors reach white. A/SPORTS tilegroup uploads preserve the interleaved character plane. |
| `nba_rom_font.c` | `81:9756-9FFD`; `IntroFont`, `FontWidth`, `CenteredFont` | Descriptor `$0C/$0E`, case mode `$18CE`, digit-cap mode `$18D0`, fixed digit width `$18D4`. Original capitals and enabled digits use the `$9B09` repeated-row path. Lowercase maps to uppercase glyphs without that expansion. Fixed numeric width has native leading/trailing padding and can grow. Glyph planes combine by OR. |
| `nba_intro_text.c` | `80:FE38-FE58`, `FEAD-FED3`; `81:9FDF`, `A163-A1A6` / `MultilineCenteredFont` | Reads original strings and palette from76, centers each original-case line, advances legal lines by font height +2 + `$18DC` (1), and draws with the verified RGB555 brightness conversion. The copyright glyph spans two 8-pixel strips. |

The shared font helper's demonstrated scope is the 2bpp `A9:8000` and
`A6:BB16` descriptors in the native license/legal and HUD captures. It is not
proof that every font format, character, allocation path, clipping edge, or
native transfer timing has been translated. The calling scene owns canvas
allocation/clearing, palette, tile packing, and upload scheduling. The original
presentation text helper has other uncorrected paths; it has not silently been
declared equivalent to the new shared helper.

References are under `.analysis/intro-exact-20260830/reference`: original bank
80/81/82 bytes, private Ghidra projects, `ea_intro_bank80_helpers.txt`,
`ea_intro_ghidra.txt`, `intro_text_bank81.txt`, and freshly generated bounded
`bank80_reference.c`, `bank81_reference.c`, `bank82_reference.c`. Bank81 C SHA256:
`125fa791cf83a33953bafcdc0d1893ce5cef19ed235f4ac7c63b827d4400501d`.
These generated C files are translation references; generating them is not
independent execution proof. ROM execution remains authoritative. Some older
Ghidra dumps have wrong M/X contexts around graphics helpers and must not be
treated as verified instruction boundaries.

## Evidence and gate classification

The natural, no-input cold-boot capture is
`.analysis/intro-exact-20260830/capture-v4`. It contains immutable Lua,
1,500 synchronous native RGB frames, raw resource snapshots, routine marks,
per-frame PPU state, ROM/Mesen identities, empty initial saves, and verified
private portable settings. Manifest SHA256:
`8121eebf0e84bec702ba351121f3df7460471a0e513aecda5ba67a7d394071eb`.

`intro_capture_resources.py` rejects duplicate JSON keys, wrong types,
unreviewed capture scripts, altered resource bytes, wrong ROM/emulator,
nonzero/invalid exit status, incomplete capture, shared runtime/save paths,
unverified settings, prior save files, or inconsistent observed Lua home.
It verifies the actual executable/settings/script files, not only manifest
booleans. RGB is used only by verification tools after resource construction.

The old intro gate's selected C hashes, optional asynchronous screenshots,
mean-error limits, and source-keyword assertions were replaced by exact
independent native RGB comparisons. No new expected image is derived from C.
The original 91 differing EA motion frames are not excused with a larger
tolerance. The new comparison includes motion0 as well as the independently
audited1–302 interval. Fixed seven top/eight bottom overscan lines follow the
attested native viewport for every frame; there is no content-dependent crop.

The audit also fixed a misleading core-safety fixture: its duplicate entries
previously had invalid bitmap sizes, so they could fail before duplicate-ID
detection. They now use individually valid entries and require the actual
duplicate-ID error. Minimal boot fixtures include real75/76 resources, while
missing resources must fail at scene initialization. Setup-audio negative
tests retain the required graphics/boot prerequisites so they reach the audio
failure they claim to test.

The full regression run initially stopped at `test_shot_assets.py`: its ROM
shot/fatigue tables passed, but its historical F12 count hash did not. The
pack now has263 rather than272 entries. The retained A1 executable/pack
reproduced all six old full/reduced debugger images. All six candidate
comparisons differ only in the metadata row, y19–25, x8–62; all other pixels
and all261 common asset payloads are unchanged. This evidence justifies the
six updated **C-only debugger** hashes; it does not grant native parity.
Old reduced-image hashes remain in `OLD_F12` as migration provenance.
Evidence: `.analysis/intro-exact-20260830/f12-directory-audit/report.json`.

Fresh final-executable visual evidence is under
`.analysis/intro-exact-20260830/final-visual-review/`: a303-frame paired video,
consecutive E/A/SPORTS/flash/hold sheets, five text-phase pairs and the full
