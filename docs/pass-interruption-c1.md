# C1: preserve the original knockdown/pass branches

Baseline: integration7002fb1. This patch fixes three original-source omissions in the existing real `cpu_try_player_knockdown_contact` caller and corrects the CPU regression's pass-domain assumption. It does not implement the unrelated B468 receiver child or merge the archived controller branch.

At the retained C frame41876, actor0 was executing an unreleased mode15 pass when actor5 knocked it into action35/mode8. The baseline always detached possession. Original86:C0F0-C107 instead tests the owner, draws RNG atC0F5, and on nonzero low two bits jumps atC0FE directly toC189. That skips both the hitter inhibit store and the C15F-C186 owner-drop block. The corrected code preserves possession on that branch without changing the RNG call or its position. Original C476 only cancels receiving modes10/14; it does not cancel passing mode15 or clear09C4.

Two adjacent source-defined stores are fixed as part of the same contract: action36 always sets the victim's vertical velocity600 atC154-C157, including a non-owner victim; only the ball impulse480 is owner-gated atC14E-C151. An actual owner drop writes0910=3EEB atC16B-C16E. The port now updates the canonical catch pointer at that boundary. No original bug is cleaned up and no HUD RNG consumption or expected native value is changed.

The original pass marker09C4 can survive interruption and recovery. It does not mean the actor is currently executing mode15. The CPU trace test therefore applies the pass-pose restriction to the actual mode15 executor. A separate `PassInterruptionGuard` requires a recorded knockdown transition from an unreleased passer, unchanged pass identities/marker/band/family/release metadata at that transition, no manufactured release during mode8, and a classified recovery with contact inhibit cleared. It also distinguishes C476's receiver-only0946 clear from A613's both-identity clear; a partial clear without the actual mode10/14 contact transition is refused. Historical both-negative identity carry retains the existing test's scope, not a new assertion that telemetry records every A613 call.

The guard's180-simulation-tick recovery bound is a C regression domain for the present uninterrupted source-timer journeys, not a general native callback schedule. Repeated knockdown, later same-frame external field writers or a newly reached recovery continuation must be attributed rather than excused with a blanket pose whitelist. The existing source-word alias gaps are not repaired here.
