# Out-of-bounds overlay

The port now publishes the original `Out Of Bounds` and `<team> Ball` overlay
when the gameplay detector produces event 3. The possession label uses the
opposite team from the last touching actor. The original font, capitalization,
centering, tile allocation and shared presentation timer are retained.

Previously the foul consumer selected kind 17, but the HUD dispatcher stopped
at the untranslated `$83:DA12` child. Its retirement also stopped at `$83:EC60`.
The new code implements the two event-3 children and their ordinary retirement.
Other foul, injury, substitution and statistics continuations keep their
explicit unsupported status.

## Original source

Fresh headless Ghidra listings and bounded C source generated by snesrecomp
are in `build/oob-20260902/reference-verified`. This is a source cross-check,
not execution of the complete recompiled game.

| Original address | Verified behavior |
| --- | --- |
| `87:92ED–93DC` | Detect bounds and preserve the last touching actor at `492D`. |
| `85:93F5–945E` | Latch event at `08F0`; select kind/sequence 17 and timer 300. |
| `83:CC10–CC7A` | Dispatch one overlay child and retire it when the signed timer expires. |
| `83:DA12–DA8B` | Clear the 1,536-byte map; allocate three column-first grids totaling 4,288 character bytes. |
| `83:DA8C–DB9C` | Read `85:9491`, choose the possession team, center its name plus a 44-pixel reservation, and right-align `83:DB9D` (`Ball`). |
| `81:9F54–A241` | Original proportional measurement, text alignment, grid layout and character upload. |
| `83:EBDB–ED46` | With no foul-out/injury continuation, clear VRAM word `04E0` for `0260` words. |

The displayed grid is 28×6 tiles at working map (2,5), starting at tile `47`.
`DA8C` uploads its 2,688 character bytes to VRAM byte `2470` and its 384 map
bytes to VRAM byte `09C0`. The remaining grids stay unpublished for event 3.
The native title and possession lines appear at screen Y 56 and 80.

The transient collision telemetry is reset each frame. A separate persistent
`hud_event_actor_raw_492d` carries the original `93D5` writer to the HUD child,
preventing an old or missing collision result from selecting the wrong team.
Overlapping score and violation character uploads share one published buffer,
so a later scoreboard replaces the prior message correctly.

## Mesen proof

`native-verified` uses an isolated Mesen installation and normal menu button
inputs. The controlled scenario changes exactly three WRAM words at the
original bounds detector: the grounded owner's X to 0, Y to 209 and Z to 0.
The original ROM detects the violation, awards possession, publishes the
message and retires it. No ROM, CPU-register, event-code or HUD-state patches
are used. `scenario.json` records every changed word and its prior value.
The earlier unattended attempt in `native` timed out without reaching this
event; it is not counted as passing evidence.

`native-proof-final/report.json` records **zero differing bytes** across the three
native child comparisons and their visible/retired uploads. The working map
and all 4,288 character bytes match, including untouched bytes. The verifier
supplies only original entry buffers to the C executable; expected exit
buffers are read afterward. All 40 captured native frames are checked, and
the displayed Rockets message matches all 2,944 original text pixels.
The repeated capture is identical to the 40 previously reviewed images.

The immutable `tests/fixtures/out-of-bounds-hud.json` contains source identities
and native output hashes, without embedding ROM graphics. The test validates
those hashes before checking both possession branches for all 29 teams,
58 retirements, 58 subsequent scoreboards and four unsupported continuations.
The original `76ers` digit spacing and East/West city-name fallback are included.

This proves child-owned data and HUD pixels. The port projects completed
uploads at its existing dispatcher boundary; it does not reproduce the
original asynchronous DMA queue or promise identical native frame latency.

## Run it

The full asset extractor now adds resource 289: 1,008 bytes containing the two
message strings and 29 possession labels read directly from the original USA
ROM. The incremental builder preserves all 266 previous resources and metadata:

```powershell
python tools/build_oob_assets.py --rom "F:\Games\SNES\NBA Live 95 (USA).sfc" --base-pack build/nba95_assets.pak --output build/new-assets.pak --manifest build/new-assets-receipt.json
```

Use that builder only for an older pack without resource 289. Gameplay init
rejects a missing or malformed OOB resource before changing game state.
The updated desktop pack already includes it.

```powershell
.\tools\run_oob_smoke.ps1 -RomPath "F:\Games\SNES\NBA Live 95 (USA).sfc"
.\tools\run_oob_smoke.ps1 -RomPath "F:\Games\SNES\NBA Live 95 (USA).sfc" -NoBuild -ThroughMenus
```

Fresh original evidence can be regenerated with `capture_oob.py --controlled`
and `regenerate_oob_reference.py`. Both accept explicit tool/output paths.
Build `oob_native_probe` with `tools/build_vector_probe.ps1`, then run
`verify_oob_native.py` with `--native`, `--rom`, `--pack`, `--probe` and a new
`--output` directory. Captures use headless Mesen and the port's CLI, without
Computer Use.
