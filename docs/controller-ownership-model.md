# Native team identity and controller ownership, 2026-08-30

This is a bounded, independently captured model and implementation plan. Human
gameplay is **not wired** in the current port. Changing `cpu_vs_cpu` alone would
enable incorrect ownership transfers and use the wrong teams' player ratings.
The next checkpoint must establish coherent native team identity before human
dispatch is enabled. No production initialization/human changes are included
with this document or the new probe.

## Native controller contract

| Player Setup `$166D+2*pad` | Screen position | Native allocator result, pad0 |
| --- | --- | --- |
| 0 | left/visitor | actor5, group5, context1 controller count1 |
| 1 | center/neutral | no actor assignment; both counts0 |
| 2 | right/home | actor0, group0, context0 controller count1 |

The other four selection words are1 in these single-controller journeys.
Actual Player Setup RGB was inspected for all three positions; this is not an
inference from a stored byte alone. The allocator was observed at entry and
exit through its production caller. During400 native court frames, the common
human action dispatcher `$84:E2AC` was reached137 times for selection0,
zero times for neutral1 and176 times for selection2. Different actors/game
states explain different dispatch counts; they are not an expected cadence
oracle for C or proof that every human action was exercised.

`$86:E208–$E24B`, called from `$86:DA85`, initializes five controller record
groups to-1, all ten actor `+$16` assignments to-1 and previous selections
`$1677+2*pad` to-1, then calls `$86:E24C–$E389`. Controller records are
`$47EB+$40*pad`. The allocator clears actor assignments and team controller
counts, distinguishes unchanged/changed selection, ignores neutral1, observes
the `$07F8` override, and allocates distinct actors to controllers on each
side. The unchanged-selection path preserves each record's selected actor.
Finally it copies current selections to previous and publishes `$1681`'s
high-bit direction-mode flag into each record `+$10`. Recomp files
`controllers_bank86.c/.txt` expose both complete routines; `$83:BBCB` is the
other observed static caller of allocation and needs a natural reallocation
journey before accepting its behavior as wired.

The real actor loop `$87:9106–$929E` obtains the controller from actor `+$16`,
looks up its record using `$87:9C71`, and skips repeat input processing when
record `+$04` is set. `$87:9B30` reads polled native buttons from `$0576+2*pad`.
`$85:EF3A–$EFEC` then publishes:

| Controller record field | Meaning |
| --- | --- |
| `+$00`, `+$02` | native team group0/5 and selected actor index |
| `+$04` | input already processed for this actor sweep |
| `+$06` | native eight-way direction,8 neutral; original lookup table depends on `+$10` |
| `+$08`, `+$0A` | current buttons and previous-sample storage, both current on exit |
| `+$0C`, `+$0E` | changed bits (`current XOR previous`) and newly pressed bits |
| `+$10` | alternate direction-table selection from Player Setup flags |

The action call `$87:91BF→$84:E2AC` receives **newly pressed** bits in DP`$AE`,
with held/current buttons retained in the record and DP`$B2`. Movement follows
only after the original FT, recovery, receiver, inbound and mode gates.
Native behavior dispatch still runs afterwards; an owned actor is not removed
wholesale from the normal scheduler. Record `+$04` is marked at `$87:9276`.
Its reset boundary must be mapped before enabling input processing in C.

Natural pause captures also establish the requesting controller's team.
`selection2-teams2-pause-v2` and `selection0-teams2-pause-v2` press Start after
600 court frames and end after `$86:818D–$81D2` publishes `$08D2`. In both cases
`$095E=0` identifies pad0; controller record `$47EB+$00` and `$08D2` are0 for
right/home selection2, and5 for left/visitor selection0. The native routine
indexes `$87:9C71` by the requesting controller and copies that record's group.
`$86:8453` later copies this group into `$4933/$4935`; the timeout counter branch
decrements `$4715` for0 and `$4795` for a nonzero group. Special override paths
through `$07F8/$08FA` or a negative requester need separate cases.

Thus `$08D2` is a native actor group0/5, not a UI boolean with0 meaning left.
The older controlled `mesen_timeout_resume_capture.lua` cases injecting0/1
still exercise the zero/nonzero counter branches but do not prove natural
controller ownership or their left/right labels. These new captures do not
choose a pause-menu item or claim timeout confirmation; an earlier attempted
menu-confirm capture is retained as incomplete because its default selected
row differed from the assumption.

Native raw button bits are B=`$8000`, Y=`$4000`, Select=`$2000`, Start=`$1000`,
Up=`$0800`, Down=`$0400`, Left=`$0200`, Right=`$0100`, A=`$0080`, X=`$0040`,
L=`$0020`, R=`$0010`. C's `NBA_BTN_*` uses bits0..11 in the opposite sequence.
Current `pad_held_raw = input->held & 0x0FFF` is therefore a host mask, despite
its raw-ROM label. Its dormant FT/inbound consumers currently expect host
masks. Introduce an explicit native conversion or renamed host field without
silently breaking those consumers.

The input publisher also applies native L/R boost only with sufficient player
stamina and consumes the Traveling rule in its original ball-owner/grounded/
moving branch. Those are part of completing the routine, not optional UI work.

`$86:BC9B–$BD1E` transfers control only if the target has no controller and
its team has controllers. It scans matching team records from the team's
round-robin cursor, transfers the selected actor, advances the cursor and
clears the old actor's assignment. It never assigns a human controller to
every new ball owner on the opposing team. Current `ball_attach_to_actor`
clears all assignments and assigns pad0 to whichever actor catches the ball
when `cpu_vs_cpu` is false. Pass/shot launch paths also clear assignments.
Those paths must adopt the native control contract before human play can work.

## Proposed representation and affected consumers

Keep native gameplay context indices0/1 and raw actor groups0/5. Context0 is
home/right for normal Exhibition; context1 is visitor/left. Session gameplay
arrays—scores, timeout counts, lineup/roster order, availability, stamina,
fouls/statistics—must explicitly use this native context order. UI team fields
remain `left_team`/`right_team`. Add one reviewed conversion at the boundary,
such as `team_id_for_native_context(session, context)` and explicit
`native_context_for_ui_side(side)`. Do not scatter opposite ternaries or swap
team art alone. Non-Exhibition `$15C3` handling is a separate proven mode input,
not a guessed boolean.

Replace the overloaded player1 boolean with native selections0/1/2 and retain
all five records when the original supports them. Keep UI side enums separate
from native actor group/context indices. A neutral controller has no timeout
team; pause/restart behavior for CPU-versus-CPU needs native evidence rather
than converting neutral to a team with a truthiness test.
